## 它怎么工作

每 20 秒对每个启用的任务走一遍：**快照（费率 + 持仓）→ 风控裁决 → 开仓前预检 → 调度决策 → 执行**。

- **方向**：每次开仓时比较两个方向的净资金费，选能收钱的那个方向；持仓期间不调头。
- **轮换**：持有时长可以是固定值，也可以是区间（每次开仓在区间里随机抽一个）；到期两边一起平，冷却后重开。
- **仓位大小**：按两边可用保证金里小的那一边算，再按任务的「开仓金额」截断。开仓金额可以填区间，每次开仓在区间里随机抽一个金额。
- **Arcus 下单方式**：每个任务可单独选「限价（挂单，0 手续费）」或「市价（吃单）」；没选过的跟随 `.env` 的 `ARCUS_MAKER`。
- **两所共有币种自动匹配**；币种下拉框按两所买卖价差从窄到宽排。

### 风控（安全动作永远压过交易动作）

1. **开仓前预检**：估算的强平距离低于 `MIN_CORRIDOR_PCT`（默认 3%）就不开；两所中价相差 3% 以上不开（防止同名不同物）；低于最小下单额不开。
2. **开仓后复核**：用真实仓位重算强平距离，比预期差就立刻两边一起平。
3. **持仓监控**：任一条腿离强平小于 `CLOSE_CORRIDOR_PCT`（默认 1.5%），或剩余距离掉到开仓时的一半，**两边同时平掉，绝不单腿止损**。
4. **孤腿抢救**：任何时候只剩一条腿，无条件市价平掉。
5. 下单请求超时**不重发、也不当成没下**，按仓位判断成没成交；开仓前先把 Arcus 的单签好，签不出来就不碰 Lighter。
6. **每个币种单独兜底**：某个币种这一轮出错（比如某个所连不上），只记一条错误，其它币种的风控和孤腿抢救照常进行。

### 强平价

Arcus 不返回强平价，程序按账户权益和维持保证金率自己算，并按**最坏情况**把账户里其它 Arcus 仓位也算成同向一起亏。
所以面板上的强平价通常比 Arcus 网页上显示的**更近**：Arcus 网页假设只有这一个币在动，程序假设账户里所有仓位一起动
（全仓下这才是整个账户真正会被强平的位置）。

### Arcus 限价挂单（可按任务选）

建任务时「Arcus 下单方式」选「限价」即可；`.env` 里的 `ARCUS_MAKER` 只是没单独选过的任务的默认值。Arcus 挂单手续费 0%，Lighter 吃单挂单都是 0%，一轮开平的手续费归零（吃单模式约 4.5 bps）。

- Arcus 挂 ALO（只做 maker），订阅 Arcus 订单推送当门铃：一有成交就立刻在 Lighter 吃单对冲，单腿窗口正常约 1 秒；推送断了自动退回每 0.5 秒轮询。
- 挂单在后台等，最多 `MAKER_WAIT_SECONDS`（默认 120 秒）；一点没成交就撤单，下一轮再挂，零成本。
- 只成交一部分时按实际数量开仓，持仓期间继续挂单**补仓**到目标数量（补仓前同样检查强平距离和保证金）。
- 正常轮换平仓也先挂单，等不到的部分改吃单；**风控触发的平仓一律立刻吃单**。
- Lighter 对冲补单几次仍失败：撤掉 Arcus 挂单，没对冲上的部分立刻吃单平掉，不留裸腿。

## 侧栏「日交易量预估」仪表盘

- **指针 / 大数字**：当前启用任务的预估日交易量（两所合计）= 每天轮数 × 4 × 单边金额（金额区间取中值）。
- **满刻度**：理论上限 —— 两边最大杠杆 + 全部权益，同时守住开仓门槛，按最短轮换 0.1 小时、吃单开平估算。
- **青色刻度**：近 24 小时实际成交。鼠标停在仪表盘上能看到每一项的算法。只是估算，不影响交易。

## 注意事项

- **同一个 Lighter 账户上还有别的程序在跑时**：不能共用同一个 `LIGHTER_API_KEY_INDEX`（nonce 会互相顶掉），
  也不要让两个程序交易同一个币种（会把对方的腿当成孤腿平掉）。
- Arcus 拒收时间偏差 30 秒以上的签名请求，请保持系统时间同步。
- Arcus 的美股等品种有交易时段，休市时杠杆上限会降低、盘口会变薄，挂单成交会明显变慢。
- 所有状态存在项目目录的 `data/`（SQLite）；删掉它等于清空任务和账本。
- **代理对两个所的全部请求都生效**，包括 Lighter 官方 SDK 的下单连接（socks5 代理靠依赖 `aiohttp-socks`，一键启动会自动安装）。代理不稳会导致对冲补单变慢，建议给两个所各配一条稳定的代理。

- **Arcus 用全仓**：强平距离按整个账户权益算，并按最坏情况把账户里其它 Arcus 仓位也算成同向一起亏。

  **杠杆直接决定离强平多远**。所以 Entropy 实际用的杠杆 = min(任务杠杆, 该币上限, 守得住开仓门槛的最高杠杆)。
  例：上限 20×（维持保证金率 2.5%）、门槛 3% → 最多 18×。任务列表会显示「实际 E 18× · A 20×」。

1. **开仓前预检**：两条腿各估一个离强平的距离，取近的那个，低于 `MIN_CORRIDOR_PCT`（默认 3%）就不开；

2. **开仓后复核**：用真实仓位重算强平距离（Entropy 用交易所给的逐仓强平价），比预期差就立刻两边一起平。

5. 下单请求超时**不重发、也不当成没下**，按仓位判断成没成交；开仓前先把 Arcus 的单签好，签不出来就不碰 Entropy。
6. Hyperliquid 的下单回执直接给出成交量：回执说成交了就按回执对冲，不会因为仓位接口慢半拍留下裸腿；
   回执里的拒单理由（藏在 `statuses[].error` 里）会被解析出来，不会把被拒的单当成功。

- Arcus 挂 ALO（只做 maker），订阅 Arcus 订单推送当门铃：一有成交就立刻在 Entropy 吃单对冲，单腿窗口正常约 1 秒；推送断了自动退回每 0.5 秒轮询。
- 挂单在后台等，最多 `MAKER_WAIT_SECONDS`（默认 120 秒）；一点没成交就撤单，下一轮再挂，零成本。
- 只成交一部分时按实际数量开仓，持仓期间继续挂单**补仓**到目标数量。
- 正常轮换平仓也先挂单，等不到的部分改吃单；**风控触发的平仓一律立刻吃单**。
- Entropy 对冲单落空时按回执立刻放宽滑点补发；补几次仍失败：撤掉 Arcus 挂单，没对冲上的部分立刻吃单平掉，不留裸腿。

### 成本

- Arcus：吃单约 2.25 bps，挂单 0。
- Entropy：只吃单，实测约 0.86 bps（Entropy 的费率以官方为准，可能调整）。
- 一轮（开 + 平，两所共 4 条腿）：吃单模式约 6.2 bps + 价差；Arcus 挂单模式约 1.7 bps + Entropy 价差。
- 面板「净损益 / 每万美元磨损」按每一轮实际成交价和手续费算，每平一次仓就更新。

## 全部设置（`.env`）

除了上面的密钥，其它都有默认值，一般不用改：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | 8005 | 面板端口 |
| `DRY_RUN` | true | `true` 演练 / `false` 实盘 |
| `ENGINE_CYCLE_SECONDS` | 20 | 引擎多久跑一轮 |
| `MIN_CORRIDOR_PCT` | 3 | 开仓门槛；也决定 Entropy 逐仓杠杆最多能用多少 |
| `CLOSE_CORRIDOR_PCT` | 1.5 | 平仓线：离强平小于它就两边一起平 |
| `REOPEN_COOLDOWN_SECONDS` | 60 | 平仓后隔多久才允许重开 |
| `ORDER_SLIPPAGE_BPS` | 10 | 吃单的滑点上限 |
| `ARCUS_MAKER` | false | 没单独选过下单方式的任务默认走 Arcus 挂单 |
| `MAKER_WAIT_SECONDS` | 120 | 挂单每次最多等多久 |

程序升级后新增的设置项会自动补进 `.env`（只追加，不改已有的行）。

## 注意事项

- **同一个 Hyperliquid 账户上还有别的程序在跑时**：不要让两个程序交易同一个币种（会把对方的腿当成孤腿平掉），
  并且给每个程序单独建一个 API 钱包（共用时同一毫秒下单会撞 nonce 被拒）。
- Arcus 拒收时间偏差 30 秒以上的签名请求，请保持系统时间同步。
- Arcus 的美股等品种有交易时段，休市时杠杆上限会降低、盘口会变薄，挂单成交会明显变慢。
- 所有状态存在项目目录的 `data/`（SQLite）；删掉它等于清空任务和账本。

## 开发

```bash
python -m venv .venv && .venv/bin/pip install -e ".[dev]"   # Windows: .venv\Scripts\pip
python -m pytest
```

`tests/` 下 355 个用例，覆盖 Arcus 签名（与 JS 实现逐字节对拍）、Hyperliquid 回执解析与价格档位、SDK 代理、
逐仓杠杆自动压低、强平价复算、超时不重发、基差闸门、挂单与即时对冲、补仓、按订单号对账、按轮次算磨损等。

代码结构（`src/parallax_hedge/`）：

| 文件 | 作用 |
| --- | --- |
| `engine.py` | 引擎：每轮串起快照、风控、预检、调度、执行 |
| `risk.py` / `scheduler.py` | 风控（含 Entropy 逐仓杠杆上限）与调度决策（纯函数，不碰网络） |
| `execution.py` / `maker.py` | 吃单 / 挂单执行；Entropy 下单走 Hyperliquid 官方 SDK |
| `arcus.py` / `arcus_ws.py` | Arcus 签名、精度、强平价；订单推送 |
| `exchanges.py` | 两所只读接口（Entropy 全部是 `POST /info`，`dex="io"`） |
| `ledger.py` / `store.py` | 成交账本与对账、SQLite 存储 |
| `api.py` / `web/` | 面板后端与前端 |
